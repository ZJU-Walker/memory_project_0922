# 0920_v0 plan (revised 2026-09-20 21:25, before any GPU work)

## Decisions (user)
- Start from the ORIGINAL pi0.5 base weights (not the 7000 task checkpoint, not the KI base).
- One run, self-writes (no stage A/B). Proposed safeguard: label-write probability 1 -> 0 over the first ~30 % of updates.
- Read: 8 learned queries, no conditioning; memory tokens at the INPUT, visible in all 18 blocks; no pointer bonus; no "Last:" slot.
- Write: every tick, no rule; token-level keys/values and the delta rule unchanged; decay 0.99 per tick.
- Short visual history as PREFIX TOKENS (not a video tower): front camera only, 4 past frames x 64 tokens, tick 1 s.
- Delete the old visual Titans bank, the side heads and the separation term.

## A. Visual history as prefix tokens
- Tick = 20 control steps (1 s). At each tick: current front + wrist frames at full 256 tokens each, plus the FRONT camera at
  t-16, t-12, t-8, t-4 (0.2 s spacing), each through the unchanged (frozen) SigLIP, 2x2 average pool over the 16x16 grid -> 64
  tokens, through the existing 1152->2048 head, plus a learned time embedding per history slot ([4, 2048], zero-init).
- Prefix order: [front t-0.8][front t-0.6][front t-0.4][front t-0.2] (64 each) [front t][wrist t] (256 each) [text] [8 memory tokens]
  [causal buffer]. The blank third camera slot is dropped.
- Padding: frames before the episode start repeat frame 0 and are masked (image mask False); the mask also zeroes their time slot.
- History dropout: with p = 0.2 per training sample all 4 history blocks are masked, so a single-frame route survives
  (copycat guard). No state-history rows: the prompt keeps the single current state (8 digits).
- Image tokens per tick: 512 + 256 = 768, the same count as v3 (which spent 256 on the blank slot).

## B. Data
- Sequence windows: 40 ticks x 20 frames = 800 frames (40 s); buckets (10, 20, 30, 40); TBPTT block 20; sampling mix as v3
  (36 / 24 / 40, later-history power 1). Per tick the loader fetches 1 wrist + 5 front frames (4 past + current); 240 frame
  decodes per 40-tick window (v3: 320).
- Labels: official sentences; boundaries fall on the 1 s tick grid (up to 1 s of quantisation).
- Prompt: "Task: <goal>, State: <8 digits>" only (no slot); max_token_len shrinks from 112 to ~80.

## C. Model plumbing
- Observation gains images["front_hist"]: [b, 4, H, W, 3] + hist_mask [b, 4]; one helper embeds it (SigLIP per frame, pool,
  head, time embedding, mask); all image call sites in pi0.py go through the shared prefix builder. Sequence loss xs carry
  [t, b, 4, H, W, 3].
- Memory tokens: 8 learned queries -> Linear 2048->512 -> unit -> x W -> [8, 2048]; RMS-scale constant calibrated to the input
  word-embedding scale (measured from the embedder), tanh gate, + slot embedding [8, 2048]; appended after the text tokens;
  visible from block 0; memory rows attend only to memory columns; exactly-zero reads masked. Layer-8 split, its per-layer
  masks, the conditioner, the instruction/prev-note shifts, the pointer bonus, the slot fields, the visual bank, the side heads
  and the separation term are removed.
- Write path unchanged: text-only key mini-pass (blocks 0..8 on the sentence tokens), whitening, values = standardised
  embeddings, delta rule with 0.99 decay; commit every valid tick with the decoded sentence (label sentence with prob p(t)).
- Loss: flow + token CE (sentence + FAST), onset weight 3, lm/fast split logged. Nothing memory-specific.

## D. Serving / offline eval
- Server ring buffer of the last 17 front frames (and states); tick every 20 control steps; builds the 4-frame history with
  padding at episode start; decodes the note (<= 48 tokens, stop at newline); writes unconditionally; returns the 40-step plan.
  Client executes 20 steps and re-queries (h20). Offline eval builds the same stacks from the recorded demos.

## E. Weight loading
- Original pi05_base params: Gemma, action expert, embedder, SigLIP matched (no regroup needed; SigLIP frozen);
  fresh: time embeddings [4, 2048], memory leaves (8 queries, key/value/query projections, slot embeddings, bank m0, gate),
  input-scale constant (computed, not trained).

## F. Configs
- pi05_robomme_0920_v0 (+ _smoke): tick 20 frames, seq 40, buckets (10,20,30,40), block 20, history 4 x stride 4 (front),
  history dropout 0.2, mem tokens 8 at input, write_every_tick, label_write_prob 1 -> 0 over the first 3k of 10k updates,
  batch 8 on 4 GPUs, lr 2.5e-5 cosine (warmup 200), save 1000, keep 2000, log_interval 10, log_diagnostics False, W&B on.

## G. Tests
- History masked == no-history model output (time embeddings zero at init); pooling shape 256 -> 64; padded-frame mask
  invariance; loader frame timestamps / padding / dropout; tokenizer prompt without slot; memory tokens at input with the
  blind mask; write-every-tick idempotence (same pairs twice == once after decay restore); server ring buffer; tiny sequence
  loss forward with history (CPU).

## H. Compute (forward FLOPs, bf16)
- Vision per tick: 6 frame passes x ~0.21 TFLOP = 1.3 TFLOP, frozen (forward only, no backward).
- LM per tick: Gemma-2B on ~1,060 tokens ~= 4.3 TFLOP; training fwd+bwd ~= 13 TFLOP + 1.3 vision ~= 14 TFLOP per tick.
- Per update (40 ticks x batch 8) ~= 4.5 PFLOP (v3: ~19 PFLOP at 49 s measured) -> ~12-18 s per update on 4xH200;
  10k updates ~= 1.5-2 days. Activation memory well under v3's (4x fewer ticks per window, same tokens per tick).
- Serving per tick: 1.3 (vision) + 4.3 (prefill) + note decode + 10 denoising ~= 7 TFLOP -> ~0.3 s on one H100 per 1 s tick.

  serving/offline 0.5, tests 0.25.
- Risks: copycat reliance on history (dropout 0.2, and the ablation is a mask flip at test time); own-writes from update 0

## Implementation notes (2026-09-20 22:20, what differs from the text above)
- History frames are separate image keys `history_0_rgb..history_3_rgb` (oldest first), not a [b, 4, H, W, 3] tensor; dict order
  is sorted, so the prefix is [front t][history 0..3][wrist t][text][8 memory tokens][causal]. The blank third camera is dropped by
  `RobommeInputs(drop_blank_camera=True)` (only when history is on; old configs unchanged).
- The old visual Titans bank, side heads and separation term are not deleted: under the flag the visual bank is not read, not
  in the sequence, and its write receives zero tokens (a plain decay). The read conditioner is simply not constructed.
- Per-step image masks now reach the training scan (they were replaced by all-ones before); gated on the v0 flag so v3 configs
  stay bit-identical.
- Loader: LeRobot `delta_timestamps` for the front camera become the interleaved grid [T x (4 past + current)];
  `SplitImageHistory` restores the current frames and emits `history_<i>` + `history_valid` from `image_is_pad` (offsets before
  frame 0 are clamped to frame 0 and masked). Per 40-tick window: 40 x 5 front + 40 wrist = 240 decodes.
- Serving: the CLIENT keeps the ring buffer (observe() on every simulator frame, as the state history already did), because the
  rollout queries the server once per 20-step chunk; the server publishes `image_history_frames/stride` in its metadata and the
  request decoder accepts `observation/history_<i>` + `observation/history_valid`.
- Configs: `pi05_robomme_0920_v0` / `_smoke` in `robomme_0920_config.py` (batch 8, fsdp 4, lr 2.5e-5 cosine to 2.5e-6, warmup
  200, 10k updates, save 1000 / keep 2000, label-write schedule 3000, W&B project robomme_0920).

## Review 2026-09-21 (what changed after the first launch)
- BUG (training): decision-tick CE/flow gated on a visual-bank commit that zero write tokens can never produce -> fixed
  (`commit_success = write_requested`, state valid from tick 0 under `memory_v0920_input_read`); test
  `test_v0920_decision_ticks_keep_their_ce_and_flow_without_a_visual_commit`.
- Speed: image tower hoisted out of the rematted tick (`memory_v0920_vision_outside_scan`, default on for the 0920 configs;
  env OPENPI_0920_VISION_HOIST=0 disables): 2 x H100, batch 4: 15.0 -> 12.1 s/update.
- Prefill: gaps shifted left under write-every-tick (newest note at full strength, older ones decay from their successor's
  onset) -- `MemorySequenceSubtasks.write_every_step` (data_loader passes the model flag).
- Serving: request-own image keys in `_sample_with_memory_v32`; write-every-tick in `V5SentenceMemory`; client ring buffer
  first-frame duplicate removed. W&B: zero-weight (< 1e-3) loss terms dropped under log_diagnostics=False.
- Known, accepted: frozen tanh gate pins every memory token to 0.5 x the word-embedding RMS (as v3); RMS floor amplifies
  weak reads to full scale (as v3, relative floor 0.16 %); flow loss does not train the read (knowledge insulation, by
  design); the text/memory RoPE positions shift by 256 when all history frames are masked (train and serve agree).

User: "start training the binfill task using exactly same setup? make full use of that 2 h100"; "before you train, you can use

- Data facts (released BinFill, 100 episodes, 60,282 frames): 266-1044 frames per episode, median 620 -- longer than
  PickXtimes (266-1025, median 543). 15 sentences: "pick up the <first|second|third|fourth> <red|green|blue> cube",
  "put it into the bin", "press the button", "All tasks completed" (lowercased for the vocabulary). 36 goals ("put two red
  cubes and one green cube into the bin, then press the button to stop"), 4-12 segments per episode (median 8), shortest
  segment 32 frames, prompt 60-65 of the 80 tokens.
- Window: the PickXtimes geometry (tick 20 frames x 40 ticks = 800 frames) would cut 23 of 100 episodes. BinFill uses a
  25-frame tick (1.25 s) x 42 ticks = 1050 frames: every released episode fits one window for ~5 % more sequence per window
  (tick 20 would need 53 ticks, +33 %). TBPTT block 21, buckets (12, 22, 32, 42), critical-start pad 5 ticks = 125 frames,
  prefill max = max(16, segments per episode + 1). Everything else is V0_MODEL / V0_DATA (horizon 40, 4 history frames 0.2 s
  apart, every-tick writes, label ramp 1.5k of 5k updates, pi05 base weights, lr 2.5e-5 cosine).
- Sampling sets (label-derived, like `_count_sentences` for PickXtimes; only sampling/state-mask bookkeeping): evidence =
  the "pick up the ..." sentences (they carry the running count), decision = those + "press the button".
- Extra demos: `cluster_robomme/generate_robomme_demos.py` runs the benchmark's own recipe
  (`robomme_benchmark/tests/_shared/dataset_generation.py::_run_one_episode`: gym.make(obs rgb+depth+segmentation,
  pd_joint_pos, seed, difficulty) + RobommeRecordWrapper + fail-aware motion planner over `task_list`, seed + attempt retries

  train 4000-13902, val 1,040,000+, test 540,000+), difficulty easy, easy, medium, hard repeating (50/25/25 like the
  release). Gotcha: the recorder buffers HDF5 frames only inside its video branch, so `save_video=True` is required (the
  first attempt with False produced 100 empty files). Output on node-local /scr/kewalk/robomme_0920/gen/BinFill.
- Conversion: `cluster_robomme/prepare_robomme_h5_to_lerobot.py --env BinFill --name BinFill200 --released <h5> --extra-dir
  <hdf5_files>`: released episodes 0-99 then generated 100-199, lossless H264 videos, task column = lowercased official
